## Key Takeaways

- Recruiters screening software engineers look for three things fast: the stack you used, the scale you worked at, and what changed because of your work.
- Every bullet should name a system, a number, and an outcome. "Worked on the backend" tells a recruiter nothing.
- Your skills section must use the exact spelling the job ad uses (Kubernetes, not K8s; PostgreSQL, not Postgres) because ATS filters match literally.
- Tailor the top third of the resume - summary, skills order, first two bullets - to each job. That is where most of the match score comes from.

A software engineer resume works when a recruiter can answer one question in ten seconds: *has this person built the kind of system we are hiring for?* That means the stack is visible at the top, every bullet carries a number, and the language matches the job ad closely enough to pass the ATS filter that runs before any human reads it.

If you already have a resume open, the fastest check is to paste it next to the job ad in the [free ATS score checker](https://www.thetailorcv.com/solutions) and see which required skills it cannot find. Then use the sections below to fix them.

## What the job ad is really asking for

Software engineering job ads are written in a code of their own. Here is how to read the four lines that appear in almost every posting:

| Job ad says | What it means for your resume |
|---|---|
| "3+ years building production services" | Show dates that add up to three years and use the word *production* in at least one bullet. |
| "Experience with distributed systems" | Name a system with more than one service and say how they talk (queues, gRPC, events). |
| "Strong CS fundamentals" | Mention data structures or algorithms work only if you did it on the job; otherwise let your projects carry it. |
| "Comfortable owning features end to end" | One bullet should go from design to launch to measured result. |

If a line is under *preferred* rather than *required*, it is a tiebreaker, not a gate - see [required vs preferred qualifications in practice](https://thetailorcv.com/blog/required-vs-preferred-in-practice).

## Software Engineer Resume Summary

Keep it to two or three sentences: your level, your stack, your best proof.

**Experienced:**
Software engineer with 5 years building backend services in Python and Go on AWS. Led the move of a payments API to an event-driven design that cut failed transactions by 38%. Comfortable owning features from design doc to on-call.

**Entry-level:**
Software engineer with a B.S. in Computer Science and two internships shipping production code in TypeScript and Java. Built a REST API serving 12K monthly users during an internship at a fintech startup.

For more formulas, read [how to write a resume summary](https://thetailorcv.com/blog/how-to-write-resume-summary).

## Technical Skills Section

Group skills so a recruiter can scan them, and order each group to match the job ad.

```
Languages:     Python, Go, TypeScript, Java, SQL
Frameworks:    FastAPI, Django, React, Spring Boot
Data:          PostgreSQL, Redis, Kafka, Elasticsearch
Cloud/DevOps:  AWS (EC2, Lambda, S3, RDS), Docker, Kubernetes, Terraform, GitHub Actions
Practices:     System design, code review, unit/integration testing, CI/CD
```

Do not list a skill you cannot talk about for five minutes in an interview. The [skills section guide](https://thetailorcv.com/blog/resume-skills-section-guide-2026) covers how many to include.

## Bullet Rewrites That Get Callbacks

The formula: **action verb + system + scale + measurable result.**

**Before:** Worked on the backend for the checkout service.
**After:** Rebuilt the checkout service in Go, cutting p95 latency from 820ms to 190ms for 1.4M monthly orders.
*Why it works:* names the system, the language, the scale and the result.

**Before:** Responsible for writing tests.
**After:** Raised unit-test coverage on the billing module from 41% to 86%, catching 3 pricing bugs before release.
*Why it works:* "responsible for" describes a job title; the rewrite describes a result.

**Before:** Helped migrate to the cloud.
**After:** Migrated 14 services from on-prem VMs to AWS ECS with Terraform, reducing hosting cost by $9K/month.
*Why it works:* "helped" hides your part. Say what you personally did - see [team vs individual credit](https://thetailorcv.com/blog/team-vs-individual-credit).

If you do not have exact numbers, estimate honestly and be ready to explain how - [estimating impact honestly](https://thetailorcv.com/blog/estimating-impact-honestly) shows how.

## Best ATS Keywords for Software Engineer Resumes

Use the ones that are true for you and appear in the job ad:

- Software development life cycle (SDLC)
- REST API / GraphQL / gRPC
- Microservices / distributed systems
- System design
- Python / Java / Go / TypeScript / C++
- PostgreSQL / MySQL / MongoDB
- AWS / GCP / Azure
- Docker / Kubernetes
- CI/CD
- Unit testing / integration testing
- Code review
- Agile / Scrum

Match spelling exactly - "JavaScript" and "Javascript" can score differently. [Exact match vs synonyms in ATS](https://thetailorcv.com/blog/ats-exact-match-vs-synonym) explains why.

## Tailoring Walkthrough: One Resume, Two Jobs

Say you apply to a **backend role** ("Go, Kafka, high-throughput services") and a **full-stack role** ("React, Node.js, own features end to end").

- **Summary:** lead with Go and event-driven systems for the first; lead with React and shipping user-facing features for the second.
- **Skills order:** Go, Kafka, PostgreSQL first for backend; TypeScript, React, Node.js first for full-stack.
- **Top bullets:** move the latency bullet up for backend; move a feature-launch bullet up for full-stack.

You are not inventing anything, only reordering. ## Common Software Engineer Resume Mistakes

1. **A wall of 30 technologies.** It reads as keyword stuffing. Keep 12-18 that you have actually used - [keyword stuffing vs coverage](https://thetailorcv.com/blog/keyword-stuffing-vs-coverage).
2. **Project names with no context.** "Built Phoenix" means nothing outside your company. Say what Phoenix does.
3. **Two-column templates.** Many ATS parsers read them out of order. Use a single column - [ATS formatting mistakes](https://thetailorcv.com/blog/ats-resume-formatting-mistakes).
4. **No links.** Add GitHub or a portfolio when your work is public.

## Frequently Asked Questions

### How long should a software engineer resume be?
One page if you have under 8 years of experience. Senior and staff engineers with significant architecture or leadership work can use two pages, as long as the first page carries the strongest proof.

### Should I put a GitHub link on my resume?
Yes, if it shows real work - a maintained project, meaningful contributions, or code you would be happy to discuss. An empty profile or one full of tutorial forks does more harm than good.

### What if I don't have one of the required skills?
Do not claim it. Show the closest skill you do have and mention you are learning the gap only if it is true. [What to do when you're missing a required skill](https://thetailorcv.com/blog/missing-required-skill-what-to-do) covers the options.

### Should I tailor my resume for every software engineering job?
Yes, but only the top third: the summary, the order of your skills and the first two bullets of your latest role. That takes about ten minutes per application and moves most of the match score.
